# API examples

These examples assume the application is running on localhost, port 8080. IDs in responses are generated by PostgreSQL and can contain gaps.

## Courts and availability

```bash
curl http://localhost:8080/courts
curl 'http://localhost:8080/courts/1/availability?date=2026-12-01'
```

Each availability entry contains `startTime`, `endTime`, `available` and `bookingId`. A free slot has a null booking ID. Times in responses include seconds.

## Create a booking

```bash
curl -i -X POST http://localhost:8080/bookings \
  -H 'Content-Type: application/json' \
  -d '{"courtId":1,"date":"2026-12-01","startTime":"10:00","endTime":"11:30"}'
```

The request requires all four fields. The court must exist. Start and end must fall within 08:00–22:00, use 30-minute boundaries, and start must precede end. The end boundary is exclusive. Zero seconds are accepted, but nonzero seconds or fractions are rejected.

Repeating the request returns 409 with this body.

```json
{"message":"Selected period is not available."}
```

The same time is permitted on another court or another date. The server checks conflicts before insertion, and PostgreSQL enforces the same rule for concurrent insertions.

## List, retrieve and cancel

```bash
curl http://localhost:8080/bookings
curl http://localhost:8080/bookings/1
curl -i -X DELETE http://localhost:8080/bookings/1
```

Successful cancellation returns 204 without a body. Repeating the cancellation returns 404. Cancellation removes the complete booking period. There are no ownership checks in this local learning version.

## Invalid input

```bash
curl -i -X POST http://localhost:8080/bookings \
  -H 'Content-Type: application/json' \
  -d '{"courtId":1,"date":"2026-12-01","startTime":"10:15","endTime":"11:00"}'
```

This request returns 400. Malformed JSON, missing fields, nonexistent calendar dates, invalid ID formats and missing availability dates also return 400. A positive ID that does not exist returns 404.
